# KAKUNIN-DEV オートデプロイスキル - 使い方ガイド

「GitHub にマージ → KAKUNIN-DEV（社内確認環境）へ自動反映」を、毎回最短で組むためのスキルです。

---

## 🚀 クイックスタート

このスキル一式（`kakunin-dev-autodeploy/`）を、お使いの AI コーディングアシスタント（Claude Code / GitHub Copilot 等）に読み込ませ、こう伝えます：

```
KAKUNIN-DEV のオートデプロイをセットアップしたいです。案件名は {案件名} です。
```

読み込ませると、必要情報のヒアリング → `deploy.yml` 生成 → 招待 → Secrets 登録 → 設置、の順で案内します。

---

## 🧭 進み方（自動 / 手動）

- **🤖 AI アシスタントが自動でやる**：情報整理、`deploy.yml` 生成、`gh` コマンド生成、（gh 可なら）招待・コミット、失敗ログ解析。
- **✋ あなたが手動でやる（案内に沿って）**：kakunin 詳細画面から S3 情報を取得、Secrets 登録（鍵はチャットに貼らない）。

---

## 📝 事前に手元に用意すると速いもの

- kakunin の詳細画面（接続パス／アクセスキー ID／シークレットキー／サブドメイン）
- GitHub リポジトリ（`org/repo`）と連携ブランチ（通常 `main`）
- 招待する相手の GitHub アカウント
- リポジトリに入れるのは「ビルド前ソース」か「ビルド済み」か（＋ビルドコマンド／出力フォルダ）

## ⚠️ よくある質問

**Q. kakunin のボタンで Git連携すればいいのでは？**
A. その機能は廃止済みで動きません。GitHub Actions 方式を使います。

**Q. 鍵はチャットに貼っていい？**
A. 貼らないでください。Secrets 登録は GitHub の UI か自分のターミナルで。

**Q. 設定したのにデプロイされない**
A. `troubleshooting.md` を参照。多くは「同期元の指定」「ブランチ不一致」「`npm ci` のロックファイル」が原因です。

**Q. Claude Code 以外（GitHub Copilot 等）でも使える？**
A. 中身はツール非依存の手順なので使えます。各ファイルを Markdown として読み込ませるか、お使いのツールの指示ファイル（例：Copilot の instructions / prompt ファイル）に内容を貼り付けて利用してください。YAML フロントマターは Claude Code 用メタデータで、他ツールは無視して問題ありません。
